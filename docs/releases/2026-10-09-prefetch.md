# 2026-10-09 页面预取循环根因修复

用户仍反馈 Edge 电脑点击等待及加载慢。本次开发基准为正式站 `d89a647530ad9728f685ef23f937630d11313929`；之前的绘制及加载优化保留，但不能据此认定用户的问题已解决。

## 根因及复现

在隔离的临时 Edge 环境中，同一版本本地生产构建页面切换明显快于正式站，最长主线程任务约百毫秒，不能解释数秒的点击等待。进一步抓取公开页面请求，发现正式站把 `Next-Router-Segment-Prefetch: /_tree` 请求返回为完整页面 `.rsc`，而本地 Next 服务返回正确的段树。

Next 16.3.1 的段缓存收到完整页面中的 `InliningHintsStale` 标志后，将该树的缓存立即过期，再次预取。正式站 HTML 与完整 RSC 的 buildId 相同，排除了这次观察由新旧部署混用造成的解释。检查官方 npm 包 `@edgeone/opennextjs-pages@0.2.10-beta.1`，其打包仅复制完整页面 `.rsc`、`.prefetch.rsc`、HTML 和 meta，不复制 `.segments`，自动 RSC 路由也没有区分段请求。

使用本次实际 Next 构建产物重放：正确段协议在 3.5 秒和 7 秒时均为 8 次树请求；模拟适配器返回完整 RSC 时，分别为 656 次、1,431 次。这是受控本地因果复现，不是正式站请求速率或所有设备的速度承诺。

## 改动与维护边界

- `next.config.ts` 使用标准 `beforeFiles` 和请求头匹配，将九个公开静态页面的段请求映射到对应构建的静态文件，并返回段协议所需响应头。普通 HTML、API、动态首页与课程、登录与同步逻辑保持原路径。
- `scripts/prepare-static-prefetch.mjs` 在 Next 构建后验证静态页及树 buildId，将框架生成的段文件原样复制到 SHA 命名空间。文件内容不改写，路由变成动态页时构建失败。
- `scripts/static-prefetch-routes.mjs` 集中列出支持的公开页面。新页面需要显式加入；账号 API 不能加入。段名称匹配拒绝点号，阻止路径穿越。
- buildId 使用既有完整提交 SHA，使静态资产与配置身份一致。无新增依赖、数据库迁移、框架源码补丁或全站缓存开关。
- 平台原生支持该版本段协议后，可以一起移除这三个文件中的兼容代码及 postbuild 命令，并保留部署协议回归验证。

## 验证与发布门槛

PR #15 的首次平台构建被 `PREFETCH_ROUTE_NOT_STATIC: /` 拦住，旧版本继续服务。首页的 `getServerViewer` 在缺少认证配置时提前返回，掩盖了其 Cookie 依赖；配置认证后首页是动态路由。使用非秘密认证占位值和官方适配器 prebuild 在本地完整复现失败。后续从静态范围排除首页，保留原有保护，并为 CI 构建配置同样的占位值及 standalone 模式，防止无认证环境再次掩盖该边界。没有放宽动态页面拒绝检查，也没有把首页或真实账号数据发布为静态文件。

新增单元检查覆盖公开静态范围、路径穿越拒绝、原字节复制、版本不匹配拒绝和动态路由拒绝。`tests/e2e/deployment-prefetch.spec.ts` 结合真实浏览器、构建产物与编译后的路由配置重放部署行为：旧配置失败，修复配置通过，暖缓存点击不新增 RSC 请求。

最终本地生产构建、类型检查、全库 lint、77 项单元测试、116 项浏览器测试（含 9 项既有视觉基线）通过。日志及正式站证据在本次 PR 和忽略目录 `outputs/root-prefetch-*`、`outputs/root-performance-*`。上线必须核对 `/api/version` 完整主分支 SHA，确认公开段响应、请求数停止增长及真实 Edge 账号导航。仅有本地 `next start` 测试不能证明 CDN 修复成功。

首次打开仍有静态资源和实时账号确认的网络成本；本次针对已证实的无限预取缺陷，不承诺任意网络下零等待。没有触发付费 AI、重置账号密码、重新导入或修改用户原论文。
