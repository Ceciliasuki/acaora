# ACAORA 七门预设课程设计

日期：2026-10-02

状态：设计草案，等待用户审阅；不是已上线课程或已通过的内容验收报告。

## 1. 用户意图与已核实的起点

用户要求：完善所有课程，由平台安排材料与学习顺序，不要求用户导入；逐门编写、逐门把关。此前建议仅做一门课程，被用户明确扩大为全部课程。

已核实：`app/courses/page.tsx` 实际包含七门课程，现有流程是选择课程 → 导入/粘贴资料 → 使用用户 DeepSeek 密钥生成练习。该页面没有预设正文、章节题库、课程学习进度。之前对话说“六门”有误，以代码中的七门为准。

默认假设：面向中文本科生系统自学，同时支持按章节复习；覆盖本科核心知识，不宣称替代某所大学的全部教学、专业认证或研究生课程。学生可以自由跳章，推荐顺序不强制锁课。用户尚未指定特定学校大纲、考试或教材版本。

成功标准：用户登录后选择任意一门课程，无需导入材料或配置 AI 密钥，就能看到完整目录、阅读讲义、理解例题、作答并检查解析；重新打开和更换设备后可继续学习。七门课程都通过下述逐门验收，才算本次内容范围完成。

## 2. 方案选择

| 方案 | 好处 | 代价与判断 |
| --- | --- | --- |
| 仓库中维护固定课程、例题和题库 | 内容可逐条审阅、版本可追溯，学习不依赖外部 AI 请求 | 编写和核验工作量较大；推荐采用 |
| 打开章节时由 AI 生成 | 初期编写量小 | 正文和答案不稳定、依赖密钥和网络；不适合作为基础课程 |
| 嵌入外部课程链接或视频 | 可利用成熟材料 | 国内访问、版权、语言和学习体验不一致；仅作为延伸阅读 |

课程正文、固定题库、来源信息随应用发布；学习记录存入现有账号体系。暂不开发课程管理后台，不增加新付费服务，不自动调用付费 AI 编写线上内容。

## 3. 内容组织与统一课件格式

每门课安排 10 章，每章 2 节，合计 70 章、140 节。每节至少 3 道固定练习，合计至少 420 道；这些数字是设计目标，不是现有内容数量。若编写中发现某节过重，可拆分增加，不能用重复内容凑数。

每节必须具有：

1. 学习目标与前置知识：说明学完能够判断或计算什么，链接到需要的本平台知识。
2. 正文：有连贯解释、符号定义、适用条件，不能只列关键词、公式和摘要。
3. 至少一个完整例题：给出题设、每一步推导或计算、结论与解释；数值题有独立复算记录。
4. 至少三道练习：一题概念辨析、一题计算/模型应用、一题解释或条件判断；逐题提供答案、解题过程和常见误区。
5. 小结与下一步：概念联系、需要复习的位置、下一节入口。
6. 来源与版本：明确原理参考、开放材料出处、内容修订版本和实际检查记录。

开放题只展示参考要点，不自动给出“已掌握”或准确分数；客观题可确定性判分。查看答案不等于答对，阅读完成不等于知识掌握。无需上传作业、购买教材或设置 API Key 才能完成基础课程。

提供必要的图、表和公式；不强制每节使用装饰插图。不先做视频、直播、证书、排名、复杂考试系统或自动生成学习计划。

## 4. 七门课程的完整目录

### 4.1 STAT-201 概率论与数理统计

前置：高中代数、函数；连续型分布使用基础积分，先提供微积分符号说明。

| 章 | 第一节 | 第二节 |
| --- | --- | --- |
| 1 概率基础 | 样本空间、事件与概率公理 | 计数方法、加法公式与概率建模 |
| 2 条件与独立 | 条件概率、乘法公式与全概率 | 贝叶斯公式、独立性与常见误判 |
| 3 离散随机变量 | 分布律、伯努利与二项分布 | 几何、泊松分布与场景选择 |
| 4 连续随机变量 | 分布函数、密度与均匀分布 | 指数、正态分布与标准化 |
| 5 多维随机变量 | 联合、边缘与条件分布 | 独立性、随机变量函数与变量变换 |
| 6 数字特征 | 期望、方差与计算规则 | 协方差、相关系数与独立性的区别 |
| 7 大样本与抽样 | 大数定律与中心极限定理 | 抽样分布、t、卡方与 F 分布 |
| 8 参数估计 | 点估计、矩估计与极大似然 | 置信区间、覆盖率与样本量 |
| 9 假设检验 | 检验逻辑、p 值与两类错误 | 均值、比例和方差检验的条件 |
| 10 综合应用 | 两样本、配对与拟合优度检验 | 从研究问题到估计、检验和结论 |

重点把关：概率不能为负或超过 1；密度与概率不能混淆；独立与不相关不同；区间覆盖率和 p 值不能表述为假设成立的概率；小样本分布条件与渐近近似区分。

| 章 | 第一节 | 第二节 |
| --- | --- | --- |

| 3 需求变化 | 收入效应、替代效应与斯勒茨基分解 | 跨期选择、劳动供给与不确定性入门 |

| 5 完全竞争 | 利润最大化、停产与退出 | 行业均衡、进入和福利 |
| 6 市场势力 | 垄断定价、边际收益与无谓损失 | 价格歧视、垄断竞争与条件限制 |
| 7 寡头与博弈 | 最优反应、纳什均衡与古诺模型 | 伯特兰、斯塔克尔伯格与策略比较 |

### 4.3 STAT-302 回归分析

前置：概率统计的估计与检验、矩阵基础。突出统计模型与预测，因果识别交给计量课深入。

| 章 | 第一节 | 第二节 |
| --- | --- | --- |
| 1 回归问题 | 响应变量、解释变量与数据结构 | 条件均值、误差和模型假设 |
| 2 简单线性回归 | 最小二乘推导与拟合 | 系数解释、残差与拟合优度 |
| 3 多元线性回归 | 矩阵表达、估计与识别条件 | 控制变量、偏回归与系数解释 |
| 4 统计推断 | 系数标准误、t 检验和置信区间 | 联合 F 检验与约束模型比较 |
| 5 变量形式 | 虚拟变量、参照组与交互项 | 对数、非线性变换与边际效应 |
| 6 模型诊断 | 残差图、异常值和影响点 | 多重共线性、杠杆值与处理原则 |
| 7 误差结构 | 异方差与稳健标准误 | 加权最小二乘与相关误差入门 |
| 8 模型选择 | 调整 R²、AIC、BIC 与比较前提 | 交叉验证、训练测试划分与泄漏 |
| 9 预测与扩展 | 均值置信区间与个体预测区间 | 正则化与非线性回归入门 |
| 10 综合实践 | 清洗、拟合、诊断和改进 | 用可复算小数据写回归报告 |

重点把关：预测不等于因果；加入变量不会让普通 R² 下降；预测区间与均值区间不同；诊断规则不是自动删样本依据；稳健标准误不修复遗漏变量偏差。

### 4.4 ECON-301 计量经济学

前置：概率统计、回归基础；微观经济学帮助解释问题。与回归课交叉内容采用明确前置链接，避免复制讲义凑篇幅。

| 章 | 第一节 | 第二节 |
| --- | --- | --- |
| 1 经济问题与识别 | 研究问题、数据结构与目标参数 | 相关关系、反事实与因果条件 |
| 2 OLS 基础 | OLS 假设、无偏与一致性 | 遗漏变量偏差与模型设定 |
| 3 推断与设定 | 异方差、稳健和聚类标准误 | 函数形式、约束检验与解释 |
| 4 内生性与工具变量 | 同时性、测量误差与内生性 | 工具变量、2SLS 与弱工具问题 |
| 5 面板模型 | 个体效应、固定效应与随机效应 | 双向固定效应、组内变换与标准误 |
| 6 政策评估 | DID、平行趋势与对照组 | 事件研究、错位实施与异质性风险 |
| 7 其他识别方法 | 回归不连续的局部识别与检验 | 随机实验、选择偏差与匹配边界 |
| 8 时间序列 | 平稳性、趋势、单位根与伪回归 | AR 模型、协整入门与预测评估 |
| 9 离散与受限结果 | Logit、Probit 与边际效应 | 受限因变量、样本选择与模型选择 |
| 10 完整实证 | 问题、识别、估计和稳健性 | 如实报告不显著结果与研究限制 |

## 5. 学习路线与页面行为

统计路线：概率统计 → 回归分析 → 多元统计。实证路线：概率统计与回归基础 → 计量经济学。经济路线：微观经济学 → 国际贸易；国际金融在宏观预备材料之后学习。

课程列表保留七门课程及统计/经济筛选。选课后先展示课程简介、前置知识、目录和“开始/继续学习”，不展示导入框和必填密钥提示。

进入章节后：左侧目录，中间正文与例题，页尾固定练习与上一节/下一节。目录支持键盘、当前节标记和小屏折叠。章节进度来自真实记录，不显示虚构学习人数、掌握度或预计收益。学习时长除非经过实际阅读评估，先不标注。

“完成阅读”是用户确认事件，不根据打开页面或滚动到底自动判断。练习记录区分未作答、作答、查看解析和客观题正误；开放题为自查。复习入口呈现已做错的固定客观题，不先增加复杂间隔重复算法。

可选 AI 追问只在用户主动调用时读取当前课节上下文，保持现有 BYOK 行为，独立标注即时 AI 输出。默认学习路径不发生付费模型请求。不保留资料导入作为课程主流程；是否提供补充材料工具留作以后独立需求。

## 6. 内容结构与学习记录

课程内容采用版本控制的静态、结构化文件，按课程与课节拆分，避免一个巨型客户端文件。正文构建为只读内容，互动练习和进度是独立客户端组件；不一次向客户端传入七门全部正文。具体文件格式与公式渲染方案在实施计划中核对依赖后确定，不预设当前仓库已有 Markdown/公式渲染库。

稳定标识：现有 course code 不变；chapterId、lessonId、questionId 发布后不随标题、顺序或文案改变。课程版本、题目版本及检查状态显式记录。

内容至少包括：标题、目标、前置链接、正文块、带解答的例题、固定练习、答案解析、误区、参考来源及修订记录。内容检查状态只允许草稿、待复核、已通过；状态必须对应实际记录，不能由“文件存在”推导为已通过。

学习记录属于当前已登录账号，至少保存：读完的 lessonId、最后阅读位置、各题尝试与题目版本、复习题、更新时间。沿用同源服务端 API 与 Supabase 账号鉴权；不信任客户端提交的 userId，不使用 service_role 客户端密钥。新增学习记录表的具体 SQL、RLS 与迁移操作在实施阶段按 Supabase 技能及当前文档核对。

离线待同步记录按账号隔离，退出或切换账号不能显示前一账号数据。阅读完成用单调合并，作答保存独立尝试 ID，避免两个设备覆盖整份进度；最后阅读位置属于继续入口，不影响完成集合。显式重置使用服务器确认的代次/版本，旧设备排队的记录不能复活已重置进度。题目答案修订后保留旧尝试的版本，提示新版需要重做，不沿用不适用的正确标记。

访问过的已缓存内容可离线恢复；不承诺尚未缓存的课节离线可读。网络不可用或云端未初始化时，明确显示本机已保存/待同步，不假称云端已同步。

## 7. 编写来源与核验方式

讲义采用原创中文解释与自行构造的例题。公开教学资料用于核实原理和大纲，逐项记录真实访问的官方 URL、章节及许可；不复制商业教材全文、图片或习题，不把本项目 MIT 许可误当成外部材料许可。候选资料未实际核实时不得标为“已验证来源”。

统计与回归：大学公开课程、开放统计教材和公开讲义；多元统计：矩阵与各方法的公开大学讲义；经济与贸易金融：开放经济学教材、公开课程、官方制度及统计说明。时效性制度事实以相关机构现行资料为准；不要写未经核验的当前汇率、关税税率或政策状态。

每门课独立走以下检查，不以一次全站测试替代：

1. 覆盖检查：10 章和全部课节有实质正文、目标、例题、习题、答案与来源，没有“即将上线”、占位或重复凑数。
2. 条件检查：公式的符号、单位、定义域、假设与解释一致；前置链接无断点，跨课程同一概念不矛盾。
3. 数值检查：逐个数值例题和题目用独立计算复算；保留输入、计算方法、结果与误差容限。不能用正文内同一个错误数值同时生成“预期值”和结果。
4. 边界检查：检验小样本与零方差、矩阵秩不足、无交易、消费者边界解、汇率反向标价等与实际章节有关的条件。
5. 题目检查：唯一答案题确有唯一答案，干扰项无意外正确选项；开放题有明确参考要点，不能假装自动判分。
6. 讲解检查：从题设可以复现解答，结论不过度推广，统计关联不当作因果；注明是模型例子还是现实资料。
7. 学习检查：从课程目录完成阅读、练习、解析、继续学习的全流程；字体、公式、图表、键盘操作在真实浏览器中可用。

AI 可以辅助起草与检查，但本次逐门把关是代理执行的来源交叉核对、程序复算与教学连贯性检查，不是任课教师或独立学科专家审阅。内容出处中如实说明编写方式和检查范围，不使用“权威认证”“专家审定”等标签。

发布前每门课产生一份验收记录，区分已验证、失败、未验证。只有所有阻断项解决才能标为可发布；来源或计算仍不确定的题目必须修正或替换，不能隐藏失败。

## 8. 实施顺序与最终验收

先建立课程内容结构、阅读与固定练习的共用组件，再按下列顺序填充和把关。顺序兼顾基础概念和交叉引用，不意味着只交付第一门。

1. 概率论与数理统计。
2. 微观经济学。
3. 回归分析。
4. 计量经济学。
5. 多元统计分析。
6. 国际贸易学。
7. 国际金融。

每门通过后进入下一门；发现共用概念错误时修复并复查受影响的已完成课程。完成全部内容后再做七门之间的衔接检查和完整应用验证。正文和进度不是“先填几篇文章再假称完成”的交付。

最终至少确认：

- 七门全部目录与课节存在，最低题量和必要正文完整，数值复算与内容验收可追溯。
- 无资料、无 AI Key 时所有基础学习路径可用，且不发送 AI 请求。
- 客观题判分正确，开放题不伪造分数，解析可见性及版本记录符合设计。
- 登录、刷新、换设备、断网重连和账号切换的学习记录行为经过实际对应测试；确定性 mock 测试不能冒充真实云端验证。
- 云端学习记录经过所有权/RLS 检查，不影响原有论文、项目数据；进度重置不被旧离线记录复活。
- 七门目录、内容阅读、图表公式、键盘和小屏至少进行实际浏览器检查；原有 PaperLab/DataLab 的必要回归通过。
- 按实际修改运行 typecheck、lint、相关单元/E2E 与生产 build；只记录本次实际执行结果。
- 同步 README 与 PRODUCT 的课程能力描述，不宣称新增能力已经上线，除非生产版本核实成功。

## 9. 设计批准边界

本文件确定课程范围、内容要求、学习行为和验收目标。它不包含已编写的 140 节正文，也不宣称已核验教材或计算。

当前采用 brainstorming 的架构改造路径：用户审阅并认可本设计后，再形成具体文件、依赖、迁移和验证步骤的实施计划；实施计划审阅及执行方式确定后开始修改产品代码。设计阶段没有数据库迁移、付费调用、生产部署或学生记录变更。
