# G1 研究任务关联方案

本轮实施范围：复用 `ProjectEvidence`、项目笔记/任务和本机 `ResearchSnapshot` v1，不新增数据库表或跨设备快照协议。

对象关系：论文段落 → 已有项目摘录（保留论文与段落 ID）→ 本机分析快照 ID / 数据指纹 → 项目笔记中的解释与下一步任务。快照选择关联时由用户选项目及可选已有摘录；提交前读取最新项目并用 `expectedOwnerId`、`expectedUpdatedAt` 保护写入。只在用户确认时把快照名称、数据身份摘要、解释和本机来源链接写入现有项目笔记，不上传数据行或分析原文件。

操作：保存命名快照 → 在分析历史选择 → 关联项目 → 指定已有论文证据、写解释、可选新增任务 → 在项目笔记中打开快照。项目已有摘录继续用原来的“返回原文”。不填造论文关联，不自动推断研究结论。

存储与兼容：项目侧沿用已有 notes 字符串和 tasks 数组。快照格式保持 v1；链接为 `/data?snapshot=<id>#history`，只有当前浏览器及当前账户的本机历史可解析。云端同步笔记中的链接不意味着快照已同步。旧快照及旧项目无需迁移；导入导出的 v1 快照恢复后才能在别的设备使用对应链接。

来源不可用：快照 ID 不存在时显示明确缺失提示，不选另一份历史代替；可导入原导出 JSON 恢复。原数据未载入时仅展示已保存摘要、指纹和配置，重新拟合仍需原文件及匹配检查。原论文删除时保留已关联摘录，原文入口按既有逻辑报告不可用。

导出恢复：使用现有快照 JSON；导入先校验格式、大小及数量，冲突 ID 不覆盖；不从导入内容自动绑定或写入任何项目。项目关联由当前用户再次明确选择。

本方案随代码一起供审查。方案本身不计功能完成；完成状态以本机往返、账户隔离、冲突保护、导出恢复和缺失来源场景为准。发布另需授权。
