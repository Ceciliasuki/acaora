## 三、A 批：保护工作与精确恢复任务

### A1. 项目笔记草稿保护

**修改对象：** `app/projects/page.tsx` 及确有必要的本地草稿存储模块。

**要实现的行为：**

1. 未保存的项目笔记在站内跳转、返回和刷新后能够恢复；明确区分“草稿已保存在本机”和“笔记已保存到账户”。
2. 草稿至少按账户 ID 与项目 ID 隔离；账户还未确认时不能恢复到默认账户或匿名作用域。
3. 保存本地草稿失败时显示准确状态，并为未保护的修改提供离开提醒。不要只依赖 React 卸载时写入，也不要把定时保存之间的最后一次输入丢掉。
4. 草稿记录应包含恢复所需的时间与保存基准。若云端笔记在草稿形成后更新，不自动用草稿覆盖它；提供查看差异、恢复草稿或保留已保存内容的明确选择。
5. 保存到账户成功后，只清除与本次成功内容相同的草稿；迟到的响应不能清除用户随后继续输入的内容。
6. 登录切换后清空前一账户的界面状态，不显示其草稿；退出时遵循现有本机数据清理政策，不擅自扩大或改变保留范围。
7. 如要增加“放弃草稿”，仅删除当前账户、当前项目的草稿，并清楚说明结果。

**必要验收：** 输入文字后站内往返、刷新；保存失败；本机存储不可用；保存中继续输入；账户 A/B 切换；云端基准发生变化。使用隔离测试记录，不能覆盖真实笔记。

**完成标准：** 每个场景都能保留最后输入，或在无法保护时明确阻止无提示丢失；不串账户、不误报云端已保存。

### A2. 最近记录精确跳转

**修改对象：** `app/dashboard/page.tsx` 和必要的目的页解析。

1. 最近论文链接使用已有论文路由协议，直达对应论文；当前已有 `paper`、`view=reader` 与可选 `paragraph` 参数，不另造一套路由。
2. 最近项目使用已有 `/projects?project=<id>` 协议。当前项目页已经解析 `project`，优先复用。
3. 缺失、已删除或不属于当前账户的目标给出准确提示；不得静默打开另一条记录并表现成操作成功。
4. URL 与当前记录保持一致；刷新、后退、重新进入能找回正确对象。已有显式段落跳转优先，普通续读使用现有保存位置。

**必要验收：** 至少两篇论文、两个项目的隔离样本；分别点击最近记录；刷新与后退；无效 ID 与不可访问目标。不能只用一个对象证明跳转正确。

**A 批停止：** A1、A2 的相关验收通过后交付，不顺便改总览视觉、论文正文或整个项目页。

## 四、B 批：文献身份与内容保真

### B1. 先确认问题发生在哪一层

检查 `app/papers/page.tsx` 的导入流程、`pdf-text.ts`、`original-pdf.tsx`、已有修复回调和书目编辑组件。

- 分别记录：已有论文实际保存了什么、当前导入器对受控副本输出什么、阅读器如何展示。
- 使用产品示例、公开论文或经授权的本机副本，不在用户已有记录上直接重导入。
- 现有书目编辑、题名编辑与原 PDF 修复入口已经存在，先检查覆盖不足和误判原因，避免再建一套编辑器。

### B2. 新导入内容的改进

1. 连续多行题名应尽量完整合并，避免只保存第一行。推断题名与用户确认题名区分，不能覆盖手工修改。
2. 支持常见带编号的主章节与子章节；避免把作者区统称为 Introduction，也不能把表格数字、列表项或普通长句误当章节。
3. 仅在有可靠版面证据时合并换行断词。保留真实连字符、负号、数值、公式和专业术语；禁止无条件删除全部连字符或空格。
4. 对高可信的重复页眉页脚和页码采取保守处理；表格、公式和无法可靠重建的区域提示查看原 PDF。
5. 章节与段落保留来源页信息。未识别部分保持中性名称，不生成伪造的章节结构。
6. 不承诺 OCR、任意复杂版式或扫描件支持，除非另行实施并验证。

**必要验收：** 多行题名、常见单／双栏、带编号的小节、正文中的表格与数字、换行断词和真实连字符等代表性用例。逐项对照原 PDF，不能用“段数增加”代替质量验收。

### B3. 旧记录只做兼容改进

1. 优先增强文献身份确认、原 PDF 入口、抽取限制提示与已有安全修复能力。
2. 不自动改写旧正文、段落 ID 或字符偏移。对题名、章节等元数据的修复，也要保护用户已确认的值。
3. 如果旧内容必须重新分段，先交付旧锚点到新锚点的映射、无法映射时的回退、备份和幂等方案；映射未证明可靠前，不写入用户记录。
4. 书目字段复用现有结构，缺失保持未知；从 Crossref 获得的信息注明来源与确认状态，不从题名臆测作者和年份。
5. 为可信识别的原文与译文设置正确局部语言；未知语言不强行全部标成英文。

**完成标准：** 新导入质量有代表性对照；原有笔记、批注、译文、阅读位置与项目来源链接仍有效。明确哪些旧记录问题尚待安全修复，不把导入器修好等同于历史数据修好。

## 五、C 批：数据分析的可操作性与可理解性

### C1. 回归配置重排

修改 `app/data/multiple-regression-panel.tsx` 及相关样式，按“因变量 → 解释变量 → 标准误 → 运行”组织。

- 保留影响方法选择的关键说明；数值上限、编码细节和长解释放进有标题的展开说明。
- 在配置过程中持续提供可达的“拟合模型”区域；可显示当前公式和可用完整样本数。未知时显示正在计算或未计算，不能填 0。
- 结果区空态简洁，避免左侧很长、右侧整屏空白。移动端按操作顺序重排。
- 设置或处理数据变化后，旧结果明确标为需重算；固定结果与当前结果不能混淆。
- 保持现有系数、标准误、样本排除、分类编码与数值稳定性政策。

**验收：** 普通笔记本高度下完成一次示例配置与拟合；键盘可达运行按钮；配置变化后的旧结果提示正确。复用已有统计正确性证据，不无故重算全部统计引擎。

### C2. 直方图补足数据语义

- 逐组提供区间与频数，显示单位或“单位未提供”，并交代实际分箱规则。
- 提供等价的频数表或可访问说明；不能只写“某变量的直方图”。鼠标提示不能成为唯一读取方式。
- 图形、区间和频数表复用同一份分箱结果，不维护第二套计算。
- 连续区间的柱形表达准确；窄屏可减少可见刻度，但不能让区间信息无法取得。

**验收：** 图和频数表完全一致，边界归属说明准确；键盘与辅助技术可以获取每组数据。除非另有已确认计算缺陷，本批不改分箱算法。

### C3. 数据保存状态

- 在数据身份附近明确说明原文件、本次载入数据、方案和命名快照分别保留在哪里。
- 登录用户的本机快照不能写成“已云同步”；匿名标签页快照也不能暗示长期保留。
- 保存、固定结果、导出方案、导出数据、导出复现包使用含义明确的标签。
- 实际操作状态变化时更新提示；刷新后需重选文件的边界应在导入前后均可发现。
- 保留本机处理政策，不为消除文案差异而自动上传原数据。

**验收：** 登录／匿名、文件载入、命名快照、刷新与重新选择文件的状态描述和实际存储一致。

### D3. AI 配置返回与检索说明

**AI：**

- 未配置 Key 时，将“配置模型”作为明确下一步；保留用户选择的论文、段落和 AI 动作。
- 配置后返回原任务，由用户点击执行，不能自动产生付费请求。

- Key 继续遵循当前会话保存政策；准确显示发送范围、未配置／运行中／失败／结果状态。
- 保留已正常的页签方向键与上下文说明。

**检索：**

- 在结果附近说明来源与宽泛匹配边界，给出当前 API 确实支持的字段、短语和类型筛选用法。
- 未确认来源支持精确短语语法前，不写“加引号即可精确匹配”。不把本页筛选冒称为全库筛选。
- 索引返回总量、当前页数量、已选数量分别表述；不把返回条数当作精度或召回率。
- 保留关键词与筛选上下文，正确处理加载、零结果、失败重试与过期响应。
- 不增加未实现的来源、筛选或 AI 推荐；用户提交前不自动把当前论文正文或笔记发往公共索引。

**验收：** 无 Key 的配置往返；模拟运行状态；检索结果、零结果与失败恢复。真实 AI 调用不属于默认验收。

## 七、E 批：提示、可访问性与手机体验

各子任务独立推进，不一次重做全部页面。

### E1. 在关键时刻说明数据去向

- 导入／同步前清楚说明：“原 PDF 不上传；提取后的论文文本与笔记按账户同步。”文案必须匹配当前账户与实际行为。
- AI 执行区域说明本次会发送的文本范围与目的服务。
- 匿名用户、本机数据分析、登录论文同步分别表述，不统一写成“所有内容仅在本机”或“全部已同步”。
- 提示简短可读，详细说明可展开；不要给每次普通操作增加重复确认弹窗。

### E2. 键盘、语言与页面身份

- 增加首个键盘可见的“跳到主要内容”，目标为真正的工作内容区，能够绕过重复导航。
- 为主要路由提供可区别的页面标题。私有论文或项目的完整题名是否进入标签标题，应遵循现有隐私政策；公共 Open Graph 不输出账户内内容。
- 检查本批新增或改动的表单标签、错误反馈、焦点回归与 live region。
- 保留正常的 Escape、页签方向键、减少运动与可见焦点行为。不要为统一样式删除焦点提示。
- 根页面保持中文；原文／译文的局部语言标记按 B 批处理。

### E3. 手机阅读工具整理

- 保留阅读、笔记、AI、检索的清楚入口；将低频文献操作归入明确的工具菜单。
- 当前论文身份、当前位置、原 PDF 与返回列表可发现；目录能显示当前项并抵达完整章节列表。
- 不让关键操作仅依赖 hover；控制浮层、焦点与返回行为，不能挡住正在编辑的内容。
- 保留已有桌面阅读位置、专注模式与侧栏折叠语义。

**必要尺寸：** 优先检查实际改动断点附近和 375px 手机、1366×768 笔记本；仅在出现新的疑点时扩展。检查长题名与一份长正文，不为每个文字改动重复全站巡检。

### E4. 帮助与反馈

- 提供可发现的帮助入口，先覆盖原文件与同步、抽取限制、草稿与快照、AI 设置和常见恢复方式。
- 反馈优先链接到已有、真实维护的渠道；没有渠道时明确记录缺口，不创建无人接收的表单。
- 不自动附带论文、数据、凭据或账户内容。需要诊断资料时，先让用户看清包含什么。

**完成标准：** 关键提示能在对应操作时被看见；键盘能进入、完成并返回；手机的主任务可连续完成。

## 八、F 批：首页与视觉规则

本批在相关行为稳定后执行。采用项目适用的界面设计技能，并遵守其工作流；不能把“奖项标准”当作任意重设计的理由。

### F1. 建立角色规则，保留页面差异

先整理一页简短的角色规范：页面身份、当前对象、内容标题、正文、元信息、主／次动作、局部导航、保存与错误状态。

- 优先消费现有令牌与组件。相同角色的字级、间距、颜色和反馈稳定；阅读、列表、数据页面保留各自合理密度。
- 保留产品蓝与 AI 语义色规则，不扩展装饰色板、不增加暗色主题。
- 不要求 H1 必须是全屏最大的字，不要求所有页面同版心，也不为统一而全部换字体。
- 保留已认可的总览构图，本批只修改与角色规范直接相关的局部不一致。
- 先完成一个有代表性的页面，再把同角色规则应用到需要的表面，避免一次改动所有路由。

### F2. 首页展示真实任务能力

- 将旧空工作台主视觉更新为当前可运行的示例任务画面，优先展示原文、笔记、来源回跳或分析结果。
- 使用产品自带或公开、获准使用的示例，清楚标注示例；不得把真实账户的论文、项目、头像、邮箱或 Key 做成公开资产。
- 保留简洁主张和可读结构。图片文字在目标显示尺寸下应可辨认，替代文本描述实际展示内容。
- 不编造用户数、评价、客户 logo、成果或速度指标；不新增无实际内容的营销区块。
- 动效只解释导航、定位与状态变化，保持可中断、减少运动与背景暂停；不添加滚动劫持或入场门槛。

### F3. 只整理本批触及的样式

- 新规则放在明确归属的模块或组件中；查明实际覆盖来源后，移除本批可证明重复、无引用的旧规则。
- 不再为了覆盖旧规则追加一层全局主题文件，不整仓正则替换字号、圆角、间距和阴影。
- 移动专用 CSS 或拆分导入前，确认服务端渲染、路由切换与当前 Next 版本行为。

**验收：** 受影响页面同角色表现一致，主任务不退化；截图中的示例与当前运行能力相符；没有私人内容进入公开资源。样式源码变小不能单独记为性能提升。

## 九、G 批：单独推进研究流程与性能

### G1. 研究流程先形成具体方案

围绕一个实际任务梳理：论文摘录 → 项目证据 → 数据／分析快照 → 解释与下一步任务。

- 盘点现有 ProjectEvidence、来源回跳和分析历史；明确缺少的关联，避免新建同义对象。
- 给出对象关系、用户操作、存储位置、不可用来源的回退、导出恢复与实现范围。
- 现有公开路由与本机快照能力可完成的部分，使用真实对象实现；不要填造关联或未完成状态。
- 涉及新持久化对象或跨设备协议时，先提交具体、可审查的方案与兼容性分析。方案交付不算功能完成。

### G2. 性能按实际瓶颈改

- 先查看是否已有与当前实现、设备和负载相符的有效数据；有则复用。
- 无有效证据时，只对有代表性的阅读与数据任务做必要采样，记录设备、构建模式、数据量、缓存和测量方式。
- 区分源码体量、压缩资源、实际传输、主线程开销与用户等待，不凭一个数字判断卡顿。
- 优先解决测得的瓶颈；保留 PDF／统计按需加载和 Worker，不通过隐藏内容、丢弃数据或改变计算精度提速。
- 工程目标可采用真实访问 p75 的 LCP≤2.5s、INP≤200ms、CLS≤0.1。实验室结果与真实用户数据分开报告。
- 只给稳定、可重复且有实际意义的检查设门槛。不要为显得严格，把所有工具和所有页面加入每次 CI。

**完成标准：** 一条完整任务的关联可追溯；性能改善有相同条件下的前后证据。未测得的改进不写成已提升。

## 十、每批交付格式

每批完成后，用简洁中文交付：

1. **完成内容：** 对应本文件哪些子任务，用户现在能完成什么。
