## A1 项目笔记草稿保护

- 每次输入同步保存本机草稿，以账户 ID 和项目 ID 双重隔离；草稿记录保存时所依据的账户笔记版本。切换页面、刷新、重新进入项目后恢复最后输入，不把本机草稿描述为已保存到账户。
- 云端保存失败时保留草稿。保存请求进行中继续编辑时，只确认已提交版本，保留并重新关联之后的输入；迟到的成功响应不能清除更新的草稿。
- 账户笔记与草稿基准不同，先展示两个版本，必须选择“恢复草稿继续编辑”或“使用已保存笔记”。未选择前禁止覆盖保存，选择后焦点回到编辑框。继续使用原 API 的 `expectedUpdatedAt` 冲突检查。
- 浏览器存储失败时保留当前页面会话的最新输入，提供重试入口，并在刷新/关闭前触发浏览器离开提醒。此时文字明确提示尚未写入本机；无法承诺强制关闭浏览器后的恢复。
- 删除项目时清理当前账户对应草稿。未修改数据库、账户同步协议或论文格式。

## A2 最近记录与精确定位

- 总览最近论文入口带 `view=reader&paper=<id>`，最近项目入口带 `project=<id>`；记录类型不再由裸路径推断。
- 项目选择同步 URL，浏览器前进、后退和刷新可回到指定项目。列表搜索不会使当前项目悄悄切换到另一条记录。
- 指定项目不存在或当前账户不可访问时，显示明确错误和返回列表入口，不自动打开其他项目；无项目的账户也不会因无效链接自动弹出创建窗口。
- 复用论文现有 URL 与阅读位置机制。对不存在的明确段落目标，显示提示并返回论文列表，避免留在无关阅读内容。
