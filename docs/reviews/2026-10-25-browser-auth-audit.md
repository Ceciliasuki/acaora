# 浏览器、账户状态与界面文案审查

日期：2026-10-25。基线：`a2fcbb2d061813fc247086f89d9fa0222660197f`。

本次检查关注真实登录状态差异、退出范围、跨标签页账户变化、延迟响应及窄屏布局，同时移除用户指定的文件上传、设备存储、账户隔离等常驻说明。课程保持独立模块，研究功能与数据存储方式不因文案删除而改变。

## 已修复的问题

| 优先级 | 原问题与证据 | 修复 |
| --- | --- | --- |
| P1 | 四种浏览器均复现：一个标签页退出后，另一个总览和设置页仍显示旧项目、旧资料。原客户端只通知当前 window。 | 用 BroadcastChannel 通知同源标签页，兼容 storage 事件；恢复焦点、可见性及页面恢复时重新确认身份。只传递变化信号，不广播用户资料或令牌。总览、设置和侧栏清除旧状态并拒绝过时响应。总览在接收项目和论文后再次确认身份，未收到标签页通知时也不采用旧响应。 |
| P1 | 设置与密码表单原先没有绑定编辑时的账户，账户切换与提交存在竞争窗口。 | 前端记录账户及操作代次；资料和密码接口验证 expectedOwnerId，不匹配时返回 409 且不写入。重置页在账户变化后失效，并取消延迟跳转。 |
| P1 | 退出代码使用 Supabase 默认 global 范围，与“当前设备”的界面语义不一致；失败也可能被当成已退出。 | 显式使用 local，只终止当前浏览器会话。上游失败返回错误，界面保留已确认的账户内容并允许重试。 |
| P2 | 手机宽度下，因果图的横向滚动区域无法通过键盘聚焦；Axe 在四种浏览器中报告 serious。 | 为滚动区域设置名称及焦点入口。保留等价的可编辑变量与边列表。 |
| P2 | 登录输入可在客户端接管前被填写，随后丢失；装饰字符进入表单控件的可访问名称。 | 输入在客户端就绪后启用；补全 name、自动填充及邮箱输入属性，装饰符号设为 aria-hidden。验证密码显示与隐藏。 |
| P2 | 访客侧栏可能显示通用用户名称，读取失败也可能被当成访客。 | 明确区分读取中、未登录、已登录和读取失败；访客入口直接进入登录。 |

Supabase 的退出范围依据：[当前会话与其他设备的退出范围](https://supabase.com/docs/guides/auth/signout)。

## 检查记录与限制

- 六项接口执行测试验证账户不匹配时无写入、密码账户绑定、local 退出及退出失败处理；15 项既有源码约束通过。
- 类型检查通过；全项目 ESLint 发现的可聚焦滚动区域规则冲突已作带原因的单行例外，新增与修复文件的检查通过。CI 继续执行项目原有发布门槛。
- 本地 Next 优化构建和类型生成完成。自定义 dist 下，既有 postbuild 默认读取 `.next` 导致失败；指定 `.next-browser-cookie` 后预取产物生成成功（10 个路由、30 个文件），未重复构建。
- Impeccable 对改动界面的检测无发现。已查看桌面和手机截图；这不等同于全站可访问性认证。
- 技术审查分项仅针对上述范围：可访问性 3/4、响应式 3/4、实现一致性 3/4。性能与主题体系本次未作全量度量，不计分，也不生成全站总分。
- Windows WebKit 的 SameSite 限制可由 [Playwright v1.62.1 自身 Cookie 测试](https://github.com/microsoft/playwright/blob/v1.62.1/tests/library/browsercontext-cookies.spec.ts) 核对：Windows WebKit 的 Strict/Lax 用例标记为预期失败。本地仅跳过该引擎的独立 SameSite 子资源行为测试；其余 Cookie 流程照常执行，Linux CI 中仍执行该项 WebKit 检查。
- Windows WebKit 会把取消的 Next 预取报告为 access-control 页面错误。trace 中对应网络结果为 `Load request cancelled`。测试仅在同一 URL、`_rsc` 预取、明确取消记录及 WebKit 同时匹配时单独记录诊断；其他 JavaScript、账户请求及真实 CORS 失败仍使测试失败。
- WebKit 自动化不能替代 macOS Safari、iOS 真机、浏览器扩展或所有隐私策略组合的验收。只测试合成账户的真实 Cookie 链路，不声称完成真实账户跨设备登录。
